使用说明

坐标、分类与数据

这个站点把原来的单文件查询页拆成了总览、地图、清单和说明四页， 数据仍然来自同一份仓库快照。

坐标怎么读

每个物品都有一个稳定编码。货架区用三段编码，柜子区用两段编码：

AL区域
2第 2 排
13第 13 格
  • AL = A 区 · 左侧，AR = A 区 · 右侧；B、C 区同理。
  • AL-2-13 读作「A 区 · 左侧 · 第 2 排 · 第 13 格」。
  • CL-07 读作「C 区 · 左侧 · 第 7 格」，柜子只有一排，所以省略排号。
  • 排号和格号都从 1 开始，格号在界面里补足两位显示。

数据与更新

站点是纯静态的，没有后端和数据库。页面里的 assets/data.js 由脚本从原始查询页提取生成， 所以更新仓库数据只需要重新生成一次：

  1. 用新的单文件查询页替换源文件。
  2. 在站点根目录运行 python tools/build_data.py --source <源文件>。
  3. 运行 node tools/test_core.js，确认数量、空位和分类测试仍然通过。
  4. 把改动提交到仓库，GitHub Pages 会自动重新发布。
更新脚本会校验区域、编码、容量、名称唯一性和总数守恒； 如果数据不完整，它会以非零状态退出，避免把坏数据发上线。

离线与隐私

所有页面、样式和脚本都使用相对路径，直接双击 index.html 也能离线使用。站点不加载外部字体、CDN 或统计脚本，也不会把查询内容发送到任何服务器。

总览页的「最近查看」只保存在你当前浏览器的 localStorage 里，最多 8 条，可以随时清空。

常见问题

为什么搜索「钻石」会出现钻石块和钻石剑？

搜索会匹配名称中包含关键词的所有物品，并按「名称完全一致 → 开头一致 → 包含关键词 → 编码命中」排序。要精确找编码，直接输入 BL-3-08 这样的完整编码即可。

地图为什么需要横向滚动？

货架每排有 44 格，完整铺开比普通屏幕宽。地图按 01–11、12–22、 23–33、34–44 分成四组，左右拖动就能看到整排。

可以把它部署到自己的域名吗？

可以。站点是纯静态文件，部署到 GitHub Pages、Cloudflare Pages 或任意静态服务器都可以，仓库里的 README 有具体步骤。
